# agent-mesh-bridge — پل ایجنت‌مش

یک سرور MCP ‏stdio تک‌فایلی و بدون هیچ وابستگی که به ایجنت‌های کدنویسی اجازه می‌دهد بین ابزارهای دسکتاپی که در آن‌ها اجرا می‌شوند — **ZCode، ‏Codeg، ‏Ghostex، ‏Claude Code و Codex** — به هم تسک واگذار کنند، در هر دو جهت.

سرور روی stdio پروتکل MCP (‏JSON-RPC خطی) صحبت می‌کند و زیر دستش به CLI رسمی هر اپ وصل است: ‏`codeg-cli` برای Codeg، ‏CLI ‏`ghostex` برای Ghostex و ران‌تایم ‏`zcode` برای ZCode. همان سرور را در همه‌ی کلاینت‌های MCP ثبت می‌کنی و بعد هر ایجنتی در هر اپی می‌تواند کار را به ایجنت اپ دیگر بسپارد.

## ابزارها (۱۰)

- ‏`codeg_status` / ‏`codeg_agents` / ‏`codeg_run` — وضعیت، فهرست ایجنت‌ها و واگذاری تسک به ایجنت داخل Codeg
- ‏`ghostex_sessions` / ‏`ghostex_agents` / ‏`ghostex_dispatch` / ‏`ghostex_send` — فهرست سشن‌ها، ساخت سشن ایجنت تازه در Ghostex و فرستادن تسک، ارسال متن به سشن موجود
- ‏`zcode_run` — اجرای یک پرامپت با ران‌تایم خود ZCode
- ‏`muse_delegate` / ‏`muse_result` — صف فایلی (inbox/outbox در ‏`~/agent-bridges`) برای واگذاری ناهم‌زمان تسک به ایجنت میزبان و خواندن نتیجه

## نیازمندی و نصب

macOS و Node.js لازم است و هرکدام از اپ‌های Codeg / Ghostex / ZCode که می‌خواهی به آن برسی باید نصب و واردشده باشند. اسنیپت آماده‌ی ثبت برای Claude Code، ‏Claude Desktop، ‏Codex، ‏OpenCode و ZCode در پوشه‌ی ‏`examples/` هست؛ مسیرها و محل باینری‌ها و پوشه‌ی صف با متغیرهای محیطی ‏`AGENT_MESH_*` قابل‌تغییرند (جزئیات در README انگلیسی).

## محدودیت‌های صادقانه

- **Gemini دسکتاپ قابل واگذاری نیست:** اپ رسمی Gemini هیچ MCP/API/AppleScript ندارد؛ فقط یک URL scheme برای بازشدن اپ دارد و ابزار اجرای تسک هم ندارد.
- واگذاری داخلی خود Codeg ‏(`delegate_to_agent`) عمداً خاموش می‌ماند؛ این مش از آن استفاده نمی‌کند — واگذاری این‌جا صریح و تک‌به‌تک از راه CLIهاست.
- فقط macOS، و وابسته به سطح CLI فعلی هر سه اپ.
